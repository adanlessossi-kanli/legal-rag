# Frontend Internationalization (i18n)

## Overview

Multi-language support for the Legal RAG frontend covering **English (en)**, **French (fr)**, **German (de)**, and **Italian (it)** using `next-intl` v4 with Next.js 14 App Router.

## Library: `next-intl` v4

[`next-intl`](https://next-intl-docs.vercel.app/) — the de-facto i18n library for Next.js App Router.

| Library | Verdict |
|---------|---------|
| `next-intl` | ✅ Best App Router integration, type-safe, active maintenance |
| `react-i18next` | ❌ Requires extra wiring for App Router, no built-in routing |
| `next-translate` | ❌ Stale, limited App Router support |
| Manual `Intl` API | ❌ No routing, no tooling, high maintenance |

## Supported Locales

| Code | Language | Label |
|------|----------|-------|
| `en` | English | English |
| `fr` | French | Français |
| `de` | German | Deutsch |
| `it` | Italian | Italiano |

Default locale: `en`

## Translation Namespace Structure

A single flat JSON file per locale with dot-separated namespaces:

```json
{
  "common": { },       // App name, nav labels, sidebar, aria labels
  "auth": { },         // Login + register forms
  "chat": { },         // Chat page, input, messages, sources
  "upload": { },       // Upload page, dropzone, status
  "documents": { },    // Documents page, table, empty state
  "errors": { }        // Error boundary fallback
}
```

See `messages/en.json` for the complete key inventory.

## Implementation Details

### Locale config — `src/i18n/config.ts`

```ts
export const locales = ["en", "fr", "de", "it"] as const;
export type Locale = (typeof locales)[number];
export const defaultLocale: Locale = "en";
```

### Request config — `src/i18n/request.ts`

Uses the v4 `requestLocale` Promise API:

```ts
import { getRequestConfig } from "next-intl/server";
import { notFound } from "next/navigation";
import { locales, defaultLocale, type Locale } from "./config";

export default getRequestConfig(async ({ requestLocale }) => {
  const locale = (await requestLocale) ?? defaultLocale;
  if (!locales.includes(locale as Locale)) notFound();
  return {
    locale,
    messages: (await import(`../../messages/${locale}.json`)).default,
  };
});
```

### Navigation helpers — `src/i18n/navigation.ts`

Uses the v4 `createNavigation` API:

```ts
import { createNavigation } from "next-intl/navigation";
import { locales } from "./config";

export const { Link, redirect, usePathname, useRouter } = createNavigation({ locales });
```

### Middleware — `src/middleware.ts`

```ts
import createMiddleware from "next-intl/middleware";
import { locales, defaultLocale } from "./i18n/config";

export default createMiddleware({ locales, defaultLocale, localePrefix: "as-needed" });
export const config = { matcher: ["/((?!api|_next|.*\\..*).*)"] };
```

`localePrefix: "as-needed"` keeps URLs clean for the default locale (`/login` not `/en/login`), while other locales get prefixed (`/fr/login`, `/de/login`).

### Next.js config — `next.config.mjs`

```js
import createNextIntlPlugin from "next-intl/plugin";

const withNextIntl = createNextIntlPlugin("./src/i18n/request.ts");

const nextConfig = {
  webpack: (config) => {
    // Suppress harmless webpack cache warnings from next-intl's
    // ICU message format extractor (dynamic import(t) expression)
    config.infrastructureLogging = {
      ...config.infrastructureLogging,
      level: "error",
    };
    return config;
  },
};

export default withNextIntl(nextConfig);
```

### Locale layout — `src/app/[locale]/layout.tsx`

```tsx
import { NextIntlClientProvider } from "next-intl";
import { getMessages, getTranslations, setRequestLocale } from "next-intl/server";
import { notFound } from "next/navigation";
import { locales, type Locale } from "@/i18n/config";

export function generateStaticParams() {
  return locales.map((locale) => ({ locale }));
}

export async function generateMetadata({ params }: { params: Promise<{ locale: string }> }) {
  const { locale } = await params;
  const t = await getTranslations({ locale, namespace: "common" });
  return { title: t("appTitle"), description: t("appDescription") };
}

export default async function LocaleLayout({
  children,
  params,
}: {
  children: React.ReactNode;
  params: Promise<{ locale: string }>;
}) {
  const { locale } = await params;
  if (!locales.includes(locale as Locale)) notFound();
  setRequestLocale(locale);
  const messages = await getMessages();

  return (
    <NextIntlClientProvider locale={locale} messages={messages}>
      <ErrorBoundary>
        <AuthGuard>{children}</AuthGuard>
      </ErrorBoundary>
    </NextIntlClientProvider>
  );
}
```

### LanguageSwitcher placement

The LanguageSwitcher appears in two locations:
- **Sidebar** (authenticated pages) — in the bottom section, above user info
- **Login & Register pages** (public pages) — fixed top-right corner (`fixed top-4 right-4`)

This ensures language switching is available on every page regardless of auth state.

### Navigation imports

All components use localized navigation from `@/i18n/navigation` instead of `next/link` and `next/navigation`:
- `Link` — locale-aware anchor
- `useRouter` — locale-aware router
- `usePathname` — returns path without locale prefix

### Dynamic content (not translated)

- Chat messages (user-generated)
- Document filenames (user-uploaded)
- Conversation titles (auto-generated)

### Locale-aware formatting

- **Dates** — `useFormatter().dateTime(date, { dateStyle: "medium" })` in DocumentTable
- **Pluralization** — ICU message syntax: `"{count, plural, =0 {No documents} one {1 document} other {# documents}}"`
- **Rich text** — `t.rich("text", { browse: (chunks) => <span>{chunks}</span> })` in FileDropzone

## Testing

- Verify all 4 locales render correctly: `/`, `/fr`, `/de`, `/it`.
- Verify locale persists across navigation.
- Verify the language switcher updates the URL and re-renders text.
- Verify `localePrefix: "as-needed"` keeps `/login` for English and `/fr/login` for French.
- Verify date formatting respects locale in the documents table.
- Verify pluralization works for document counts and source counts.
- Verify language switcher is accessible on login/register pages (top-right corner).
- Verify no hardcoded user-visible strings remain.
