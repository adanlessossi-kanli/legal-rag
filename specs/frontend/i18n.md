# Frontend Internationalization (i18n)

## Overview

Add multi-language support to the Legal RAG frontend for **English (en)**, **French (fr)**, **German (de)**, and **Italian (it)** using Next.js 14 App Router best practices.

## Approach: `next-intl` with App Router

Use [`next-intl`](https://next-intl-docs.vercel.app/) — the de-facto i18n library for Next.js App Router. It supports:
- Static and dynamic rendering
- Client components (`useTranslations` hook)
- Server components (`getTranslations`)
- Middleware-based locale detection
- URL prefix routing (`/en/...`, `/fr/...`, `/de/...`, `/it/...`)

### Why `next-intl` over alternatives

| Library | Verdict |
|---------|---------|
| `next-intl` | ✅ Best App Router integration, type-safe, active maintenance |
| `react-i18next` | ❌ Requires extra wiring for App Router, no built-in routing |
| `next-translate` | ❌ Stale, limited App Router support |
| Manual `Intl` API | ❌ No routing, no tooling, high maintenance |

## Supported Locales

| Code | Language | Label |
|------|----------|-------|
| `en` | English | English |
| `fr` | French | Français |
| `de` | German | Deutsch |
| `it` | Italian | Italiano |

Default locale: `en`

## Translation Namespace Structure

A single flat JSON file per locale with dot-separated namespaces:

```
{
  "common": { ... },       // Shared labels (app name, nav, actions)
  "auth": { ... },         // Login, register, logout
  "chat": { ... },         // Chat page, messages, input
  "upload": { ... },       // Upload page, dropzone
  "documents": { ... },    // Documents page, table
  "errors": { ... }        // Error messages
}
```

## Translation Keys

See `messages/en.json` for the complete key inventory. All user-visible strings in the current codebase are extracted and organized by namespace.

## Implementation Steps

### 1. Install dependency

```bash
cd frontend
npm install next-intl
```

### 2. Create locale config — `src/i18n/config.ts`

```ts
export const locales = ["en", "fr", "de", "it"] as const;
export type Locale = (typeof locales)[number];
export const defaultLocale: Locale = "en";
```

### 3. Create request config — `src/i18n/request.ts`

```ts
import { getRequestConfig } from "next-intl/server";
import { notFound } from "next/navigation";
import { locales } from "./config";

export default getRequestConfig(async ({ locale }) => {
  if (!locales.includes(locale as any)) notFound();
  return { messages: (await import(`../../../messages/${locale}.json`)).default };
});
```

### 4. Create navigation helpers — `src/i18n/navigation.ts`

```ts
import { createSharedPathnamesNavigation } from "next-intl/navigation";
import { locales } from "./config";

export const { Link, redirect, usePathname, useRouter } = createSharedPathnamesNavigation({ locales });
```

### 5. Add middleware — `src/middleware.ts`

```ts
import createMiddleware from "next-intl/middleware";
import { locales, defaultLocale } from "./i18n/config";

export default createMiddleware({ locales, defaultLocale, localePrefix: "as-needed" });

export const config = { matcher: ["/((?!api|_next|.*\\..*).*)"] };
```

Using `localePrefix: "as-needed"` keeps URLs clean for the default locale (`/login` instead of `/en/login`), while other locales get prefixed (`/fr/login`, `/de/login`).

### 6. Move pages under `[locale]` segment

Move all pages from `src/app/` into `src/app/[locale]/`. The `[locale]/layout.tsx` wraps children with `NextIntlClientProvider`.

```tsx
// src/app/[locale]/layout.tsx
import { NextIntlClientProvider } from "next-intl";
import { getMessages } from "next-intl/server";
import { notFound } from "next/navigation";
import { locales } from "@/i18n/config";

export default async function LocaleLayout({ children, params: { locale } }) {
  if (!locales.includes(locale as any)) notFound();
  const messages = await getMessages();

  return (
    <html lang={locale}>
      <body>
        <NextIntlClientProvider messages={messages}>
          {children}
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

### 7. Update components to use `useTranslations`

Replace all hardcoded strings with translation calls:

```tsx
// Before
<h1>Sign in to Legal RAG</h1>

// After
const t = useTranslations("auth");
<h1>{t("login.title")}</h1>
```

### 8. Add LanguageSwitcher component

A dropdown in the Sidebar (or header) that switches locale:

```tsx
"use client";
import { useLocale } from "next-intl";
import { usePathname, useRouter } from "@/i18n/navigation";
import { locales } from "@/i18n/config";

const labels: Record<string, string> = { en: "English", fr: "Français", de: "Deutsch", it: "Italiano" };

export default function LanguageSwitcher() {
  const locale = useLocale();
  const router = useRouter();
  const pathname = usePathname();

  return (
    <select
      value={locale}
      onChange={(e) => router.replace(pathname, { locale: e.target.value })}
      className="text-xs bg-surface border border-border rounded-lg px-2 py-1.5 text-foreground"
      aria-label="Select language"
    >
      {locales.map((l) => (
        <option key={l} value={l}>{labels[l]}</option>
      ))}
    </select>
  );
}
```

Place it in the Sidebar, above the user info section.

### 9. Update navigation links

Replace `next/link` and `next/navigation` imports with the localized versions from `@/i18n/navigation` in all components that use `Link`, `useRouter`, `usePathname`, or `redirect`.

### 10. Handle dynamic content

- **Chat messages** — User and AI messages are NOT translated (they are user-generated content). Only UI chrome (buttons, labels, placeholders) is translated.
- **Document names** — Not translated (user-uploaded filenames).
- **Conversation titles** — Not translated (auto-generated from content).
- **Date formatting** — Use `useFormatter` from `next-intl` for locale-aware date display:
  ```tsx
  const format = useFormatter();
  format.dateTime(new Date(doc.uploaded_at), { dateStyle: "medium" });
  ```
- **Pluralization** — Use ICU message syntax for counts:
  ```json
  "documentCount": "{count, plural, =0 {No documents} one {1 document} other {# documents}} in your knowledge base"
  ```

## Testing

- Verify all 4 locales render correctly by navigating to `/`, `/fr`, `/de`, `/it`.
- Verify locale persists across navigation.
- Verify the language switcher updates the URL and re-renders text.
- Verify `localePrefix: "as-needed"` keeps `/login` for English and `/fr/login` for French.
- Verify date formatting respects locale.
- Verify pluralization works for document counts.
- Verify no hardcoded user-visible strings remain (search for quoted strings in JSX).

## SEO & Metadata

- Set `<html lang={locale}>` dynamically in the locale layout.
- Generate `metadata` per locale using `getTranslations`:
  ```tsx
  export async function generateMetadata({ params: { locale } }) {
    const t = await getTranslations({ locale, namespace: "common" });
    return { title: t("appTitle"), description: t("appDescription") };
  }
  ```
- Add `alternates.languages` to metadata for hreflang tags.

## Env Config

No new environment variables required. Locale detection is automatic from the URL path.
